- Working memory：当前上下文环境中 正在被模型使用的记忆，这一刻看见什么
- Scratchpad 草稿纸：当前任务的工作台，用来暂存中间判断、工具结果分析、规则核对和下一步计划，这一刻正在怎么算
- Episodic / semantic / procedural memory 经验/语义/程序性记忆：跨会话的 事件、知识、流程等长期记忆，哪些记忆值得跨会话留下来
- Memory trace ：记录一次记忆如何被写入、取回、使用和淘汰的仪表盘

### 3.长程任务不偏移

整个任务执行逻辑 重点 推理部分优先做（

1. 首先根据任务设定锚，用于保存长期goal、约束、成功检验逻辑。
2. 任务拆分为多个里程碑，针对里程碑构建DAG链路作为todo list，同时机械态存储任务需要的参数具体值（问题：机械态怎么知道需要保存什么参数？还是来着不惧纯增量）。
3. 然后选择DAG链路的第一步去执行，然后每次执行都要记录 event 包含四大因素（做啥 为啥 咋验证 状态变啥了），给出执行时，由调度层识别和规则填入对应的参数值。

**至此一个完整的长程任务执行架构已经搭建 后续都是优化长程稳定性**

4. 我们的整个任务执行系统，记录当前的里程碑、锚和集，保留复述函数、漂移哨兵agent、验证闸门。
5. 复述就是把锚和当前里程碑 以及集等元素构建一份提示词加进去，多次工具调用自动返回上下文尾部。（多次工具调用就自动触发）
6. 哨兵就是按照event或者里程碑为规则，启动检查判断是否还合理一旦检查出不合理，拉回下一步的执行计划（重新构建当前DAG链路） 。

**我们如何对于一个中断任务进行重启**

7. 我们的恢复机制，把 锚 集 里程碑 机械态等等给到重启的agent 继续执行。

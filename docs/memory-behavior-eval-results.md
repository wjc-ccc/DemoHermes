## 怎么测的

实际启动本机 HTTP 后端，使用生产 Gateway、AgentLoop、后台提炼 Worker 和 SQLite。每轮评测使用新的独立数据目录和不同的测试用户，结束后关闭这次启动的后端。

测试输入和预期在调用模型之前确定，覆盖个人资料、稳定偏好、持续事实、四种结果的经验，以及不应该长期保存的内容。随后检查数据库卡片、逐字证据、公开搜索与读取工具，并在新会话里验证回忆。

跨会话样例还覆盖职业更正、偏好变化、遗忘和重复陈述。离线测试覆盖评测器本身、渐进批次、中断轮次、重试、版本冲突和用户隔离。

## 发现的问题和处理

1. **模型输出的格式没有讲清楚。** 真实模型曾输出 `confidence: "high"` 和引文数组，合法职业事实因此被拒绝。提示词补充了数值类型、来源 ID 到逐字引文的映射和格式示例；严格解析保留。
2. **经验与持续事实边界不清楚。** 单次实验曾因含项目名被分类为持续事实。提示词明确区分长期背景与已观察到的操作结果，并允许单次经验附带适用限制。
3. **成败校验误解否定表达。** “尚未找到成功方案”曾被当成成功。Reviewer 和 Validator 现在共用成败线索检查，先排除否定的成功表达；测试覆盖中文、英文、真实矛盾以及“不同环境通过”这种不含否定的表达。
4. **中文数字改写被当成编造。** 原文“一秒、两秒”曾被模型改写成“1 秒、2 秒”，触发数字锚点拒绝。当前代码支持中文数字与阿拉伯数字的对应核对，提示词也要求尽量保持原文写法；复核已通过。
5. **新会话的修改信息和旧值需要关联。** 当前提示词要求沿用已有事实槽位，更正和删除共用运行时来源检查；跨会话更正、偏好变化、遗忘及去重均有通过记录。

评测器也做了防误判：卡片存在不等于正确；类别、独立事实、结果极性、额外卡、逐字证据和检索都要检查。无效模型输出被拒绝后留下零张卡，也不能算成模型正确选择了空结果。

## 仍然存在的限制

- **模型与网络仍可能波动。** 曾出现 TLS 连接失败和回复超时，失败报告已保留，不能用单次成功证明长期稳定。
- **Skill 反思存在同步等待。** 当前生产装配会在轮次提交 hook 中调用 Skill 反思；慢模型调用可能延迟主回复。这属于实际观察到的超时风险，本报告不将其认定为已修复。
- **当前检索为关键词。** 本评测没有验证尚未实现的语义或混合检索。
- **关键含义断言不能覆盖所有语义错误。** 这些案例能检查规定场景的漏提取、误提取和查回情况；更复杂的隐含表达、长原文截断及多事实冲突仍需要扩充案例。

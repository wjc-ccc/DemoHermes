# Skill 自进化闭环（实现说明）

> 日期：2026-08-15  
> 状态：已落地主链（确定性事实 → draft 候选 → shadow replay → 正式晋升）

## 一句话

技能是版本化的 Markdown 程序性资产。对话成功只负责写出 **draft 候选**；能不能进 L1 / 被 `use_skill` 加载，必须过 **同一份 EvalSuite 的影子回放**：零回退，且至少改善一个 case。

## 数据流

```text
commit_turn(TurnRecord + Session.tool_calls)
    → build_turn_facts()          # 不读 EventBus
    → Distiller / Creator / LLM   # 只写 draft
    → SkillRepository.apply()     # 原子写 + revision + 审计
    → SkillReplayWorker（后台）
         复制 data/skills → 假想晋升
         EvalRunner.run(suite) × 2
         compare_reports(baseline, candidate)
         通过才 promote_after_replay
    → 下一 turn 的 SkillSelection 才看得到 active
```

主回复路径只做廉价写候选。评测在后台线程跑，不阻塞用户。

## 硬规则

1. **draft 不可被发现也不可被猜到**：`summaries_prompt` / `use_skill` / 本 turn 冻结的 `SkillSelection` 都不含 draft。
2. **EventBus 只做观测**。沉淀与晋升只认已落库的 `TurnRecord` + `ToolCall`。
3. **所有写入走 SkillRepository**：create / patch / promote / disable / rollback。模型 `skill_manage` 不能改 status。
4. **内置技能只读**。`source=builtin` 拒绝自动变更。
5. **本 turn 冻结**：`AgentLoop` 在 turn 开始时 `select()` 一次；中途写盘只影响下一 turn。
6. **失败归因**：只把「当前 `use_skill` 之后、下一次 `use_skill` 之前」的失败记到该技能上。
7. **没有考题就保持 draft**。生产默认不接真实 LLM EvalRunner；接上 `runner_factory` 后才会自动晋升。

## 技能形态

仍然是单文件 `SKILL.md`（frontmatter + 正文）。frontmatter 值单行化，杜绝 `---` 注入。`revision` 是正文版本，状态迁移不改 revision。

## 测试怎么来

- 固定 `EvalSuite`（版本 + 内容指纹）。
- 自动沉淀时用**当轮用户原文**生成最小 origin case（技能出现在 L1、turn 完成、工具失败数为 0）。
- 同一 suite 里的其余 case 天然是回归集。`compare_reports` 拒绝任何已通过 case 变失败，也拒绝「仍通过但工具失败变多」。

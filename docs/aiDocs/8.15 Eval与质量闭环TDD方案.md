> 日期：2026-08-15  
> 分支：`feat/eval-20260815`

## 0. 一句话结论

控制面（Channel → Gateway → Loop → Memory → Evolution 旁路）已经闭环。  
缺的不是再加 Plugin / 向量 / 更多 Channel，而是把「下一 turn 的上下文是否变好」变成**可复现、可回归的评测**。

本方案只新建一个深模块：**Eval**（`run(suite) → Report`）。  
装配、抽取、进化门控的升级都挂在评测结果后面，避免盲飞扩类。

## 1. 我们现在站在哪

### 1.1 控制面（已闭环）

```text
Channel
  → Gateway（锁 / Session / 斜杠命令）
      → MemoryManager.build_context → MemorySnapshot（本 turn 冻结）
      → AgentLoop.run_turn(..., assembly_policy)
      → SqliteSessionStore.commit_turn
      → EvolutionScheduler.notify（旁路）
           ├ MemoryReviewer
           ├ Reflector → Gate → PlaybookCurator
           ├ Distiller / SkillCreator / Optimizer / SkillGate
           └ EnvSnapshot / Audit / HeldOut（启发式字串门控）
      → 下一 turn 的 snapshot / L1 skill 才看见变化
```

| 层 | 状态 | 说明 |
|----|------|------|
| Channel / Gateway / Loop | ✅ | 竖切通；生产 Session 走 SQLite |
| Memory 1–14 | ✅ | Hot / Daily / transcript / Provider / Reviewer |
| Evolution 0–6 | ✅ 已接线 | `main.build_gateway` 挂 playbook + skills + assembly |
| Context 装配 | ⚠️ 浅 | `AssemblyPolicy` 偏布尔；`SkillSelector` 杠杆未吃满 |
| Held-out | ⚠️ 双层 | 原字串预筛保留；逐 case Replay 比较器已落地，生产候选隔离待接 |
| Eval | ✅ 基础可用 | 真实 Gateway turn、实际模型 messages、多 turn、JSON/Markdown Report |
| recognitionDocs | ⚠️ 部分漂移 | 需在 E0 与现役实现对齐 |

### 1.2 真正卡在哪（质量面半开）

1. **写进去的记忆有没有用**（Extractor / Curator 精确率）  
2. **装进 prompt 的东西是否该装**（SkillSelector / Budget / Daily）  
3. **进化提交后任务是否不回退**（真 held-out = suite 回放，不是字串规则）

现有单测（memory + evolution）覆盖 seam 契约，**不证明「进化让任务变好」**。

### 1.3 设计红线（延续 7.14 / 7.23 / 8.04）

1. Loop 不写盘、不认识 Channel；进化在 persist 之后旁路。  
2. 本 turn 快照不可变；写入只影响下一 turn。  
3. 记忆变更只经 `MemoryManager.apply`。  
4. **不改 `run_turn` 签名塞评测**；Eval 在旁路或独立 runner 里调公开 API。  
5. 主回复路径不被 Eval / Reflector 阻塞。  
6. 测试只打公共 seam；不 mock Manager / Store / Builder / Reviewer 自己。

## 2. 目标架构：质量闭环

### 2.1 核心命题

> **质量闭环 = 用固定 suite 度量「上下文资产」是否让任务不回退。**  
> Eval 是保险丝；装配 / 抽取 / 进化提交都必须能被 Report 打分。

### 2.2 Eval 深模块（唯一新建）

```text
EvalRunner.run(EvalSuite) → EvalReport
run_ablation(AblationRequest) → AblationReport
compare_reports(baseline, candidate) → ReplayGateResult
```

| 概念 | 含义 |
|------|------|
| `EvalSuite` | 名称、版本、一组 case；重复 case id 和空 suite 在类型层拒绝 |
| `EvalCase` / `EvalTurn` | 隔离场景 + 多 turn；用 `TurnExpectation` 类型化表达期望 |
| `EvalReport` | 逐 case/turn 结果、稳定失败码、实际模型调用证据、Markdown 摘要 |
| `AblationReport` | baseline 与关闭某层/单资产后的任务、成本、回退对比 |
| 证据面 | 同一次真实 turn 的模型 messages、回复、持久化状态、tool/skill 事实；禁止 turn 外二次计算 |

确定性脚本模型进入必跑 CI；真实模型只作为 `slow` benchmark。环境用 `EnvironmentSnapshot` 冻结模型名 / prompt hash / tool schema / skill 内容 hash。

### 2.3 与现有组件的关系

| 现有 | Eval 如何用它 |
|------|----------------|
| `HeldOutSelector` / `HeldOutTask` | E4 升级为「候选变更 → 在 suite 子集上回放 → 不降级才 admit」 |
| `AssemblyPolicy` / `AssemblyRecorder` | E3 断言装配变瘦、偏好不丢；E5 字符数进 Report |
| `EnvironmentSnapshotter` | 每次跑 suite 绑定一份快照，保证可复现对比 |
| `EvolutionCommitGate` | 继续管预算/去重；真质量门交给 Eval Replay Gate |
| Offline ACE（8.04 P4.3） | 挂在 E4 之后：离线优化 playbook/systemPrompt，用同一 suite 验收 |

### 2.4 五个对外接口保持小（加深不摊薄）

| 模块 | 对外接口 | Eval 相关复杂度藏哪 |
|------|----------|---------------------|
| Gateway | `submit` / `ask` / … | 不长业务；Eval 可走 ask 或直接 Loop |
| MemoryManager | `build_context / read / apply / search` | 抽取质量、压缩、检索 |
| ContextBuilder | `building_context(...)` | query 条件装配、围栏、预算 |
| EvolutionScheduler | `register` / `notify` | 蒸馏、门控；提交前可调 Eval |
| **Eval** | **`run(suite) → Report`** | replay、断言、基线对比 |

删除测试：若拿掉某个新类，复杂度只是回到上表五个接口内部，那个类就不该存在。

## 3. 落地切片（可勾选）

原则：每 Slice 可独立验收；先红后绿；只打公共 seam。

### E0 — 收口契约与文档对齐（无新功能）

**目标**：代码、测试、recognitionDocs、本方案指向同一套运行时。

- [x] recognitionDocs：evolution 从「接口预留」改为「已接线旁路」；SessionStore 生产默认 SQLite  
- [x] 主路径图与 8.04 / 本方案一致（snapshot → Loop → commit → evolution hook）  
- [x] `pytest -q` 全绿（基线）

**不做**：新模块、改 Provider 面、上 FTS/向量。

---

### E1 — Eval 最小面（最高优先）

**目标**：公共 seam 定死，报告只使用真实 turn 证据。

- [x] `EvalSuite / EvalCase / EvalTurn / TurnExpectation / EvalReport / EvalRunner.run`
- [x] 删除 `EvalAssertion(kind, value)` 字串解释器，避免 kind/value 错配
- [x] 删除 turn 外另算 snapshot/skill summary；记录模型 adapter 实际收到的 messages
- [x] 每 case 独立 Memory/SQLite runtime；Runner 可重复运行且不泄漏记忆
- [x] completed 与 persistence_succeeded 分开报告
- [x] pytest 入口：`tests/eval/test_eval_runner.py`

**验收**：断开 Gateway 的 Memory/Skill 注入时对应 Eval 必红；当前通过。

**不做**：真模型、多 turn 进化、接 HeldOut 生产路径。

---

### E2 — 记忆抽取评测集

**目标**：Extractor 有精确率/召回回归，而不是调 prompt 碰运气。

- [x] JSON 数据集 45 cases：profile / memory / daily / no-write
- [x] 覆盖招呼、一次性任务、问句、引用/假设、敏感信息、日志、正负偏好、中英文、事件
- [x] 同时断言 target / content / scope / provenance；未完成与中断 turn 拒写
- [x] 修正 RuleBased 的“任意长陈述进 Daily”高假阳性：Daily 必须有事件信号
- [x] Reviewer 对 `Manager.apply(ok=False)` 不再误标 done
- [x] 通用 Classification Report：accuracy、macro precision/recall/F1、逐标签指标与错误 case
- [ ] ModelBased / Fallback 补齐 fallback rate 与敏感信息误写率

**验收**：改坏规则或假模型输出后，对应 case 失败；好基线全绿。

---

### E3 — Context 装配评测 + 加深 Builder

**目标**：下一 turn 该看见什么，由评测驱动，而不是整包注入。

- [x] 相关 Skill 进入实际模型请求，无关/draft Skill 不进入
- [x] 无匹配为空；多匹配 top-k 稳定且只取 5 个
- [x] Memory 与 Skill 证据分层为 `memory_text / skill_text`，避免历史消息造成假阳性
- [x] 同步 Reviewer 多 turn：本 turn 不见新记忆，下一 turn 可见
- [x] Daily / Provider policy on/off 进入独立实际 messages 证据
- [ ] Provider 失败 diagnostic、围栏攻击、预算裁剪顺序与超限 case
- [ ] 修正 `AssemblyRecorder` 当前记录全量未选择 Skill 字符数的问题

**验收**：装配回归绿；短问场景 skill 摘要字符数低于改造前基线阈值。

---

### E4 — Replay Gate（真 Held-out）

**目标**：候选 playbook / skill 假想应用后，在 suite 上不降级才 commit。

- [x] `compare_reports` 做逐 case 单调比较；总分不变但 case 互换也判回退
- [x] 生成型资产要求“零回退 + 至少一个目标 case 改善”
- [x] suite/version/case set 不一致拒绝比较
- [ ] 自动复制 baseline/candidate 的 Memory/Skill/Session 资产并运行同一 suite
- [ ] 与 `EvolutionCommitGate` 串联：预算/去重通过后，再跑 replay
- [ ] 失败写 `EvolutionAuditLog`，不抛主路径  
- [ ] 预留 Offline ACE：同一 suite 对比「优化前/后」playbook 种子

**验收**：故意写入有害 playbook 条目 → admit 拒绝；有益条目在 suite 上通过率不降。

---

### E5 — 观测进 Report

**目标**：Trace / 装配字符数成为评测原料，不只是前端装饰。

- [x] Report 带实际模型调用次数、总/最大上下文字符数、稳定失败码
- [x] `EvalReport.to_markdown()` 输出 case 矩阵；Pydantic 原生输出机器可读 JSON
- [x] `AblationReport` 输出任务通过率/上下文字符变化、回退/改善 case 与保留建议
- [ ] Report 补齐各层裁剪前后字符数、裁剪原因、是否 `context_budget_exceeded`
- [ ] （可选）按 `turn_id` 落 JSONL/SQLite，供回放；不另起空转 trajectory 表

**验收**：只看 Report（或 frontier 链路）能回答「为何没召回某记忆 / 为何裁了 skill」。

---

### E6 — Skill 自动生成、沉淀判定与消融

**目标**：Skill 不是“写出文件 + 成功两次就 active”，而是有任务证据的程序性资产。

- [x] 最小全链：`SkillProposal → 强制 draft → shadow active → Eval 改善 → 消融回退 → 正式 active`
- [x] LLM 即使提议 `status=active`，`SkillCreator` 也强制写 draft
- [x] Skill 正式晋升支持 `promote_after_replay`，要求改善 case
- [x] 消融结论：关闭后回退→保留；关闭后改善→删除；无变化→冗余；有得有失→证据不足
- [ ] 将 shadow copy/evaluate 封装进 Replay Gate，禁止调用方手工改候选文件
- [ ] 生产 `_evolve_skills` 从计数晋升切到“候选→suite→Replay→commit”
- [ ] 增加错误描述导致误选、正文步骤错误、Optimizer patch 回退、重复/冲突 Skill 负例

**验收**：自动生成 Skill 只有在目标任务至少改善一例、既有 held-out 零回退且成本不过阈值时才 active。

## 4. 推荐推进顺序

```text
已完成：E0 → E1 → E2 RuleBased → E3 首批 → E4 比较器 → E5 首批 → E6 最小 Skill 链
当前：E3 Daily/Provider/预算 + E6 Skill 负例
  → E4 候选资产自动隔离
      → 生产 Skill/Playbook 提交门
          → ModelBased/Fallback 与真实模型 slow benchmark
              → 之后才考虑：Offline ACE / FTS5 / 向量 / Plugin
```

**为什么 Eval 先于继续扩 evolution 类**：类已经够；缺的是「变好」的证据。  
**为什么先于 FTS/向量**：没有抽取/检索评测，向量只会把噪声记更牢。

## 5. 明确后置（现在做是稀释架构）

| 先别做 | 原因 |
|--------|------|
| FTS5 / 向量库 | 无检索/抽取评测前，噪声会被记更牢 |
| Plugin 动态加载 | 只有一种加载方式时 seam 是假的 |
| Redis / 多进程 writer | 方案已定单进程 |
| 更多原子 Tool / 新 Channel | 控制面够用；缺质量 |
| 继续扩 Reflector / Creator 类 | 等 E1/E4 能度量再改 |
| Gateway 变厚 | 记忆/装配/评测逻辑不得进 Gateway |

渠道与工具可按使用需要插，但不是本方案主线。

## 6. 成功标准（产品级，可勾选）

对应 8.04 §9，改为 Eval 可勾选：

1. **可见进化**：连续同类失败后 playbook 出现可指认避坑条目，且 E2/E4 suite 能观测到下一 turn snapshot 含该条目。  
2. **主路径稳定**：开启进化后延迟可控；关闭开关行为与今日一致；Eval 不进主回复关键路径。  
3. **无 collapse**：长程模拟后 Hot ≤ 预算；关键条目在 refine 后仍存活（抽检 + suite）。  
4. **Skill 闭环**：自动生成 draft skill 经 Gate/Replay 后可被 L1/`use_skill` 复用，E3/E4 有对应 case。  
5. **契约兼容**：不破坏 7.14 / 7.23 seam；既有 memory/evolution 回归全绿。

## 7. 风险与对策

| 风险 | 对策 |
|------|------|
| Eval 测到私有实现 | 只断言 TurnResult / snapshot 文本 / AssemblyChoice / Trace 公开字段 |
| 真模型贵且抖 | E1–E3 默认假模型；真模型套件另标 `@slow` / 手工跑 |
| Replay 拖慢主路径 | Gate 只在进化旁路同步或限流队列跑；失败降级为拒绝提交 |
| Suite 过拟合 | 抽取集与装配集分离；定期加「不写」与「无关 skill」负例 |
| 文档再次漂移 | E0 验收含 recognitionDocs；本方案进度表随 Slice 勾选 |

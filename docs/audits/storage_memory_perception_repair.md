## 已实施

- Perception 使用持久事实 ID 生成读回引用；普通工具和 Action 工具都分配唯一事实 ID，provider ID 仅用于协议配对。
- 缺失或同批重复的调用 ID 在助手消息写入前规范化；解析参数不会因缺少原始字符串而变成空参数。
- 过期规则按配对成功 observation 判断；重复 provider ID 按消息位置匹配。Action 已确认成功的效果也参与过期判断。
- 读回误判只统计本轮实际发送的准入投影；shadow 和没有节省成本的投影不会误计。
- 工具 schemas 纳入输入预算；实际主模型请求的 max_tokens 使用输出预留。
- 未提交 turn 独立保留全部构建；数据库提交后再释放到滚动统计窗口。轮级计数累计，预算压力取峰值。
- 失败轮次保留真实错误的完整工具协议配对，跳过未完成助手正文和 Gateway 失败回复。
- 主模型每次调用和重试记录 usage、耗时、错误、结束原因、返回模型和响应标识。未知用量保留 NULL；轮次汇总和 SQL 列均持久化。
- Memory v13 输出 cards/skipped；初步提炼后独立复核建卡准入，并对非法提案、经验关键词和跳过引用执行一次有限修复。模型必须给出保存理由和未来用途；全部调用、最终跳过决策及用量进入Trace。
- Memory 原文按来源和预算分组，长来源带偏移分片并完整覆盖，证据仍对完整数据库原文核验。
- Memory、Anchor 与 memory 工具正文改为文本视图，结构化数据仍保存在机器字段中。
- 新增010迁移：核心 JSON 列按实际内容命名、轮次结束/错误列明确命名、删除文档登记闲置字段；此前迁移文件保持不变。
- ToolCall 使用 duration_ms/result_data；只在反序列化入口兼容旧字段名。message_count 从消息列表或 SQL COUNT 派生。
- 统一 eval_datasets/cases/questions/runs/results；问题字段契约版本、历史结束轮次、有效记忆检查点已支持。运行结果绑定发布问题指纹，语义复核不能改写实际回答。

# 120 场景正式评测结论

2026-10-12。正式数据版本 1.0.0，评分版本 `core-benchmark-score-v2`。生产 memory、perception 和提示词逐文件指纹保持不变；本次新增评测设施，没有用实验答案调受测模块。

完成 120 个 40/80/120 轮场景、360 个冻结问题；四组各重复三次得到 4,320 回答，24 场景连续六问得到 864 回答，合计 **5,184**。有效评分 **5,142**，仍有 **42** 个严格结构/匹配评分错误保留为未知。第二次盲评 951 条，345 条在答案、卡片匹配或违规上有分歧；主评分保留，两次使用同一模型，未进行人工裁判。

**结论：当前 perception 没有保持质量；冷启动含辅助 token 后也没有得到合格收益。memory 能找到大部分已经提取的正确卡，但建卡精度、负例、更正、期限及遗忘边界尚未达标。**

## 四组消融

P 表示 perception，M 表示长期 memory。关闭 M 时原文搜索和读取仍保留。每组 1,080 个正式回答，未知评分保守不计正确。

| --- | ---: | ---: | ---: |
| 两者关闭 P0M0 | 1005 / 1080 | 93.06% | 0 |
| 仅 memory P0M1 | 1036 / 1080 | 95.93% | 22 |
| 仅 perception P1M0 | 799 / 1080 | 73.98% | 0 |
| 两者开启 P1M1 | 827 / 1080 | 76.57% | 11 |

纯 perception 题库有 60 场景，每个配对比较 540 次回答；跨会话组合题单独统计。

| 固定 memory 状态 | perception 关 → 开正确率 | 差异 | 场景聚类 95% 区间 | 非劣结论 |

本次 P1 装配为生产预算分级与 Anchor，`AdmissionPolicy(mode="off")`，JEV 未参与。该数字不能推广到 active trim / defer。P1 整体均未达到 90% 质量门槛。

## perception 的实际 token

可完整比较的纯 perception / M0 冷启动结果：

| 量 | perception 关闭 | perception 开启 | 变化 |
| --- | ---: | ---: | ---: |
| 整轮全部主模型输入 | 9,020,187 | 1,675,408 | 减少 81.43% |
| 高干扰组整轮主输入 | 7,083,363 | 1,165,423 | 减少 83.55% |
| 含辅助工作的产品输入 | 9,020,187 | 13,226,365 | 增加 46.63% |
| 产品输入 + 输出 | 9,269,903 | 14,224,984 | 增加 53.45% |

所有失败都在统计中。主输入减少包括压缩失败后没有调用主模型的情况，因此不能称为质量合格的优化。M1 的完整主输入和产品总量有一次失败请求 usage 缺失，节省保持未知。

连续六问固定 M1，累计第 1 / 3 / 6 问正确率分别为：P0 95.83% / 94.91% / 94.91%；P1 68.06% / 75.93% / 75.23%。到第 6 问，两组实际主输入分别为 9,663,174 / 1,651,650，减少约 82.91%，质量没有达标。

实际产品调用还有八个中断请求，以及四个已结束失败请求缺少 usage。中断请求保留，未计为零；完整产品总成本和复用净节省不能确认。已返回产品调用均已归属，未归属数量为零。裁判调用独立，不混入产品成本；未给价格，结论只针对 token 与调用量。

下表只用 memory 与 combined 题库，每组 540 检查点、936 个有效事实观测。未知评分保守不计识别或正确卡片，数值是下界。检查点观测可以重复同一事实或卡片，不能理解为独立用户或唯一卡片数量。

| F1 | 88.06% | 86.57% |

| 尚未知的事实观测 | 38 | 20 |

| 正确卡片检索 Recall@5 | 92.31% | 91.92% |

分类字段只在部分盲评输出中提供：两组分别 343 / 343、327 / 327 个已报告的语义对应类别正确；348 / 540、352 / 540 检查点缺少类别字段。**不能据此声称总体分类精度 100%。** 该项证据不完整。

2026-10-12 方法复核补充：原 `negative_false_positive_rate` 的实现是负例场景中 `cards > 0` 的检查点比例，没有进一步要求裁判将这些卡片判为无持久用途或禁止。例如 `formal_memory_negative_00 / repeat-1 / q3 / P0M1` 保存了“不要从材料反推本人职业、口味和实验结果”的规则卡，裁判认为是合理元信息。因此 2 / 27 严格表示负例有卡率，不能直接声称已核验的错误建卡率；真正的误建需要区分规则卡与错误存入的第三方/临时信息。原始统计数值与评分保留。

答案判定也存在边界：`formal_perception_unique_tail_00 / repeat-1 / q3 / P1M0` 给出了正确值和路径，却称没有中段与末尾各自的数据，裁判仍按现有必需含义判通过。本题标准只要求最终值与路径，不能完整验证模型确实读取了两个位置。现有正确率是自动裁判的运行与语义通过率，未经独立人工逐题验真。

更正、遗忘和期限的零违规要求没有满足。跨正式与复用题统计，更正有 9 次答案违规、11 次禁止卡观测；遗忘有 16 次答案违规；期限有 14 次答案违规、1 次禁止卡。成功 / 失败 / 混合经验的答案违规分别为 4 / 7 / 0。具体问题、回答、卡片和两次判定保留在失败列表和逐次工件中。

## 失败原因与下一步

正式 P1M0 / P1M1 的正常完成数量为 892 / 879（各 1,080）；Anchor 压缩失败为 180 / 185，预算超限为 8 / 15，另有一次后台记忆准入冲突进入失败记录。

已核对的具体样本 `formal_combined_constraints_01 / repeat-2 / q3 / P1M1`：完整 JSON 经估算为 2,094 token，超出 2,048 上限；重试输出上限降为 1,024，API 以 `length` 结束，JSON 截断，最终压缩失败。优先修复预算反馈和生成重试的配合，然后测试长读回后的受保护上下文增长。memory 优先收紧临时信息与第三方信息准入，再检查更正、遗忘及期限；检索效果优于建卡精度。

这些是后续修复建议，本次按冻结计划没有修改生产模块。

## 完整性与交付

21 项评测设施定向测试通过。5,184 个回答键完全覆盖；题目哈希、未来历史检查、perception 配对原始来源及硬检查失败均为零；生产与原评测代码指纹一致。数据库有 48 个独立运行、5,184 条结果、外键及题目哈希检查无错误；42 个评分未知在数据库为 pending。

原 v3 的工具 `context` 列表解析错误通过独立评分版本修复，未改生产输出与黄金答案，原有效评分不重抽样，原评分及修复历史均保留。合成模板、固定模型、同模型裁判与重复观测都限制了对真实线上分布的推断。

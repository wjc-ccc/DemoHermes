# 正式题库发布前审查

这些问题来自数据生成器与标准的静态审查，记录时尚未查看语义评分结果。只修订未发布的正式草稿，不修改试运行已冻结的题目、答案或生产模块。

- `invalidation` 与 `outcomes` 目前使用相同的失败读回时间线，尚未真实覆盖旧记录已明确作废后的未知值。正式版需要加入明确的作废事件及禁止沿用旧值的答案。
- memory 的单次成功、失败、混合经验在不同长度上重复同一观察。正式版需要不同的环境、输出格式和真实结果，不仅改变场景 ID 与噪声长度。
- 三个条件偏好场景应覆盖不同触发条件；当前主要重复概念解释与实现细节。
- 第一个检查点之前已经出现的长期处理要求及条件偏好，也应进入该检查点的有效卡片标准，即便当前问题只问一次观察。这属于标准覆盖遗漏，不能据此把合理卡片判成误存。
- 跨会话问题应明确项目、设备或格式，避免仅用“这次”“这个项目”造成指代歧义；不得在问题中泄露成败或更正后的答案。
- 期限事实应明确北京时间，防止自然语言零点与 UTC 来源时间之间产生八小时解释差异。
- 冷启动成本与实际唯一调用总量应分列；输入和输出之和也应报告。缺失 usage 保持未知。
- 连续复用在评分前记录检索候选，不能用六问结束后的数据库状态补齐早期召回。该设施问题已经修复并由离线测试覆盖。

试运行里的 production Anchor 解析失败属于受测模块的真实结果，应保留；不得为了达到正确率目标修改模块或排除失败题。
